### 6. Performance Evaluation *(Is the speedup real and explained?)*

**6A. Top-Line Results**

- **Best Case:** *X* speedup vs. *Y* baseline on *Z* scale.
- **Typical Case:** Median performance across the suite.
- **Worst Case / Regressions:** Where does it lose, and why?

**6B. "Why is it faster?" Evidence**

- **Bottleneck Removed:** What metric proves it? (e.g., BW utilization, profiling trace).
- **Roofline / Upper Bound:** Used? How close is it to theoretical peak? (Compute vs. Memory bound).
- **Profiling Breakdown:** Kernel time vs. Comm time vs. Preprocessing vs. Sync.
- **Overlap Validation:** Is there empirical evidence (timelines/counters) that overlap actually happens?
- **Ablations (Crucial):** Impact of turning each component on/off. Sensitivity to hyperparameters.
- **New Bottleneck:** After this optimization, what dominates the runtime now?

**6C. Scaling Credibility**

- **Strong Scaling:** Fixed total size. Where does efficiency drop off?
- **Weak Scaling:** Fixed size per node. Does efficiency stay flat?
- **Comm Scaling:** Allreduce/Alltoall behavior; topology effects.
- **Load Imbalance:** Any evidence of per-rank time distribution?

**6D. Overheads & Hidden Costs** *(Force the paper to be explicit)*

- **Preprocessing / Format Conversion:** Time + memory overhead. Is it amortized?
- **Data Movement:** Are PCIe/NVLink/host staging transfers included in the total time?
- **Memory Footprint:** Peak memory usage and fragmentation risks.
- **Energy/Power:** If claimed, is the measurement methodology credible?

### 🚨 HPC Reviewer "Red Flags" *(Fast Triage)*

**Fairness / Baseline Issues**

- [ ]  **Sequential Strawman:** Compares optimized GPU code against a naive, single-threaded CPU code.
- [ ]  **Missing Obvious SOTA:** An open-source, community-standard baseline exists but was ignored.
- [ ]  **Unfair Tuning:** Authors heavily tune their method but use default, untuned parameters for baselines.
- [ ]  **Apples-to-Oranges Math:** Comparing FP16 to FP32, or algorithms run for fewer iterations without proving convergence.

**Measurement / Methodology Issues**

- [ ]  **Noise Ignored:** No repeat runs or variance reported on noisy distributed/cloud clusters.
- [ ]  **Hidden Overheads:** Excludes preprocessing, data transfer, or comm setup from "end-to-end" time.
- [ ]  **Phantom Overlap:** Claims compute/comm overlap without providing hardware timeline/counter evidence.
- [ ]  **Cherry-Picked Data:** Only reports matrix sizes or node counts where their method explicitly wins.

**Generality / Practicality Issues**

- [ ]  **Over-Fitted Hardware:** Hard-coded to a single GPU generation using many magic constants.
- [ ]  **Memory Blow-up Hidden:** Method requires massive format expansion or extra buffers that aren't reported.
- [ ]  **False Application Claims:** Evaluated only on micro-benchmarks, but makes grand claims about end-to-end application impact.
- [ ]  **Vaporware Artifacts:** Artifact/Code is promised but the pipeline is highly unclear or closed-source proprietary dependencies are required.
